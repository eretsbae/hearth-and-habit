# 콘텐츠 전략 & 주제 드리프트 방지 설계

## 검토 결과 요약

사용자 질문: *"게시물이 트렌드 위주로 주제가 중구난방 바뀌지 않도록 할 필요가 있는지?"*

**결론: 필요하다. 트렌드 추적을 아예 배제하고 고정 니치 구조를 채택했다.** 근거:

1. **AdSense 수익 구조상 evergreen이 유리** — 트렌드 글은 발행 직후 잠깐 트래픽이 오고 소멸하지만, evergreen 글은 검색 유입이 수년간 누적된다. 자동화 블로그는 글이 쌓일수록 수익이 커지는 구조여야 유지 비용 대비 이득이 난다.
2. **토픽 권위(topical authority)** — 구글은 한 분야를 깊게 다루는 사이트를 그 분야 검색에서 우대한다. 주제가 중구난방이면 어떤 분야에서도 권위가 쌓이지 않는다.
3. **스팸 판정 리스크** — 뉴스/트렌드를 자동 재생산하는 사이트는 구글의 "scaled content abuse" 정책에 걸리기 쉽다. 좁은 니치의 실용 가이드는 상대적으로 안전하다.
4. **AI 생성 정확도** — 시의성 콘텐츠는 모델 지식 컷오프 문제로 오류가 나기 쉽다. 보편적 생활 지식은 정확도가 높다.

## 니치 선정: Home & Practical Living

북미 타겟 후보 니치 비교:

| 니치 | AdSense RPM | 경쟁 | AI 정확도 | YMYL 리스크 |
|---|---|---|---|---|
| 금융/보험 | 매우 높음 | 매우 높음 | 위험 | 높음 (E-E-A-T 요구) |
| 건강 | 높음 | 높음 | 위험 | 매우 높음 |
| 테크 하우투 | 중간 | 중간 | 버전 변화로 부정확해지기 쉬움 | 낮음 |
| **홈/생활 실용** | **중상** (홈서비스·보험·유틸리티 광고주) | **중간** | **높음** (보편 지식) | **낮음** |

→ **Home & Practical Living** 선정. 광고주 수요(홈서비스, 에너지, 가전, 보험)가 탄탄하고, 계절마다 검색이 반복되는 evergreen 주제가 무한하며, AI가 틀리기 어려운 보편 지식 영역이다.

## 드리프트 방지 메커니즘 (코드 레벨)

1. **고정 필러 5개** (`config/topics.yml`) — 모든 글은 이 안에서만 생성된다:
   - Home Maintenance & Repairs
   - Cleaning & Organization
   - Energy & Utility Savings
   - Kitchen & Food Habits
   - Yard & Outdoor Basics
2. **사전 큐잉된 주제 40여 개** — 트렌드 API·뉴스 피드를 전혀 사용하지 않는다. 발행 순서는 "발행 수가 가장 적은 필러 우선" 회전 방식이라 카테고리 균형이 자동 유지된다.
3. **자동 보충도 필러 안에서만** — 대기 주제가 5개 미만이 되면 Claude가 새 주제를 제안하는데, 프롬프트가 (a) 필러 슬러그 강제, (b) "5년 뒤에도 유효한 주제만", (c) 기존 글과 중복 금지를 요구하고, 코드가 필러 슬러그를 검증해 벗어난 제안은 버린다.
4. **중복 방지** — 글 생성 프롬프트에 기발행 글 목록을 넣어 핵심 내용 중복을 금지한다.

## 편집 품질 규칙 (프롬프트에 하드코딩됨)

- 통계·연구·전문가 인용 날조 금지; 수치는 "typically/roughly"를 붙인 통상 범위만
- 가짜 개인 경험담 금지
- 미국 단위(°F, $) 우선, 짧은 문단, 스캔 가능한 구조, 자연스러운 FAQ 섹션
- AI 자기 언급 금지, 필러 문장("In today's fast-paced world") 금지

## 품질 게이트 (발행 전 2중 자동 검증)

구글의 실제 정책은 "AI가 썼는지"가 아니라 **"scaled content abuse"** — 대량 생산·저부가가치·
획일적 콘텐츠, 검색 순위 조작이 주 목적인 콘텐츠 — 를 문제 삼는다. 애드센스 콘텐츠 품질 심사도
같은 맥락이다. 이를 코드 레벨에서 방어하기 위해 `generator/generate_post.py`에 발행 전
자동 게이트를 넣었다 (`enforce_quality_gate`):

1. **프로그래매틱 체크** (무료, 즉시): 최소 글자수(기본 700단어) 미달, H2 섹션 2개 미만,
   의심스러운 소수점 통계(예: "37.4%") 패턴, 금지된 필러/자기언급 문구 포함 여부를 정규식으로 검사.
2. **독립 Claude 크리틱**: 글쓴이(작성 Claude)와 별개의 프롬프트로 "이 사이트를 스팸으로부터
   지키는 편집장" 역할을 부여해, 유용성·독창성(기발행 글과 겹치지 않는지)·구체성·정확성 신중함·
   자연스러운 구조 5개 항목을 0~100점으로 채점하고 pass/fail을 반환.
3. 둘 중 하나라도 실패하면 지적된 문제를 그대로 Claude에게 돌려주는 **1회 자동 재작성**을 실행 후
   재검사. 그래도 실패하면 **발행하지 않고** 해당 주제를 `topics.yml`에 `status: needs_review`로
   남기고(사람이 나중에 검토·재큐잉 가능) 자동으로 다음 대기 주제로 넘어간다 — 품질 미달 콘텐츠가
   그냥 통과되어 나가는 일은 없다.
4. **구조 다양성**: 발행 글 수 기준으로 5가지 글 구조("단계별 가이드", "비교/선택 가이드",
   "체크리스트", "오해 바로잡기", "문제해결 Q&A")를 순환 적용해, 모든 글이 똑같은 템플릿처럼
   보이는 것 자체가 스팸 신호가 되는 것을 방지 (`prompts.CONTENT_ANGLES`).

설정은 `config/site.yml`의 `generation.quality_gate`에서 조정 가능 (임계 점수, 최소 단어수,
재작성 횟수, 한 회차에 추가로 시도할 주제 수 등).

## 키워드 전략 전환: 헤드 텀 → 롱테일 질문 (2026-07-27)

**문제**: 3주간 17편을 발행했는데 조회수가 사실상 0. 원인은 콘텐츠 품질이 아니라
**키워드 선택**이었다. 초기 주제 큐는 "How to Fix a Running Toilet", "Gutter Cleaning",
"Lawn Care Tips" 같은 **헤드 텀**이었는데, 이 검색어들의 1페이지는 The Spruce, Family
Handyman, Bob Vila, Home Depot 같은 수십 년 된 고권위 사이트가 점유하고 있다. 도메인
권위가 없는 신규 blogspot 사이트가 이런 SERP에 진입할 확률은 사실상 없다 — 좋은 글을
써도 아무도 볼 수 없는 자리에 놓이는 셈이다.

**전환**: 대기 주제 전체를 **롱테일 질문형**으로 교체했다.

| 이전 (헤드 텀) | 이후 (롱테일 질문) |
|---|---|
| How to Fix a Running Toilet | Why does my toilet run for a few seconds then stop on its own? |
| The Right Thermostat Settings | Is it cheaper to hold one thermostat setting all day or adjust it? |
| Gutter Cleaning: How Often | Do you still need to clean gutters if you have gutter guards? |

롱테일 질문이 신규 사이트에 유리한 이유:
1. **경쟁 희박** — 이런 구체적 증상 질문은 대개 포럼 스레드나 흩어진 댓글만 답하고 있어,
   제대로 쓴 글 하나가 상위에 올라갈 여지가 있다.
2. **의도가 강함** — 지금 집에서 문제가 발생한 사람이 검색하는 말이라 이탈률이 낮다.
3. **피처드 스니펫 / AI 답변 인용** — 질문형 제목 + 첫 문단 직답 구조는 구글 스니펫과
   AI Overviews·챗봇 인용에 그대로 들어간다. 신규 사이트가 상위 순위 없이도 노출되는
   거의 유일한 경로다.

코드 반영:
- `config/topics.yml` 대기 주제 31개를 전부 롱테일 질문으로 교체 (5개 필러 균형 유지)
- `prompts.REFILL_*` — 자동 보충 시에도 헤드 텀 금지, 증상/결정/제약 기반 질문만 제안
- `prompts.ARTICLE_SYSTEM` — 제목이 질문이면 **첫 문장에서 곧바로 답**하도록 규칙 추가
  ("나중에 설명하겠다"가 아니라 실제 답). 스니펫 확보의 핵심.

기존 발행 17편은 그대로 둔다 — 삭제하면 사이트 볼륨이 줄어 애드센스 심사에 불리하고,
내부 링크 자산으로서의 가치는 유지된다.

## 오프사이트 채널: Pinterest (2026-07-27)

**진단**: Search Console URL 검사 결과가 전 URL `검색됨 - 현재 색인이 생성되지 않음`.
robots.txt 차단도 noindex도 아니다 — 구글이 URL을 알고는 있으나 **크롤 예산을 안 쓰는**
상태다. 원인은 신규 blogspot 서브도메인 + **외부 링크 0개**. 인터넷 어디에도 이 사이트를
가리키는 링크가 없어서 구글이 우선순위를 줄 근거가 없다. 수동 색인 요청은 대증요법이고,
근본 해결은 실제 외부 링크 확보다.

**채널 선택**: 홈·생활 니치에서 Pinterest는 (a) 도메인 권위와 무관하게 사람이 유입되고,
(b) 핀 자체가 크롤 가능한 외부 링크가 되며, (c) 검색 색인보다 훨씬 빠르게 효과가 난다.

**구현** (`generator/make_pin.py`):
- 글마다 **1000×1500 세로 핀 이미지** 자동 생성. 히어로 SVG는 1200×630 가로라 그대로는
  Pinterest에 부적합하므로, **그 글의 히어로 일러스트를 래스터화해 상단 밴드에 배치**하고
  아래에 제목 카드를 얹는다 (CairoSVG + Pillow, cairo가 없으면 기본 모티프로 폴백).
- **핀마다 이미지가 달라야 한다**: Pinterest는 새로운 고유 이미지("fresh pin")를 우대하고,
  이미지 인식으로 핀을 분류해 관련 피드에 배치한다. 같은 템플릿에 텍스트만 바꾼 이미지는
  신선도 점수를 못 받고 주제 분류도 안 되며, 신규 계정에서는 자동 생성 신호가 된다.
  필러별 칩 색상으로 시각적 구분을 한 겹 더 준다.
- 제목 타이포 자동 맞춤. 발행·대기 49개 제목 + 120자 극단 케이스 전부에서 텍스트 블록이
  하단 구분선을 침범하지 않음을 검증했다.
- `content/pins/PINS.md` — 핀 이미지 경로 / 보드 / 연결 URL / 복사용 설명문이 정리된
  **핀 큐**. 발행 워크플로우의 Blogger 게시 단계 뒤에 실행되어 새 글 URL이 자동 반영된다.
- 사람이 할 일은 주 1회 5분, PINS.md 보고 Pinterest에 업로드하는 것뿐.

## 플랫폼: Blogger (peterpb.blogspot.com)

원래는 커스텀 도메인 + GitHub Pages로 설계했으나, 사용자가 이미 보유한 Blogger 블로그에
애드센스 연동이 상당히 진행되어 있는 것을 확인한 뒤(지급 정보 확인·광고 설정 완료 상태) 전환했다.
도메인 구매·DNS·소유권 인증 없이 즉시 시작할 수 있고, blogspot.com 서브도메인은 애드센스가
공식 지원하는 사이트 유형이라 오히려 승인 신뢰도가 높다. 위 드리프트 방지 설계와 편집 규칙은
플랫폼과 무관하게 그대로 유지된다. 자세한 내용은 [blogger/SETUP.md](../blogger/SETUP.md) 참고.
