## 0. 한 줄 결론

글을 더 쓰는 것으로는 통과하지 못한다. 6번의 거절은 글 수 43→51→70편, 2,000단어급, 리서치 기반

**(1) 사람이 직접 한 흔적(사진·실측), (2) 책임자 식별, (3) 대량 생산 티 제거, (4) 자연 클릭 발생**
네 가지가 모두 갖춰진 뒤 **11월 셋째 주 이후** 1회만 제출한다. 글 발행은 폭을 넓히지 말고
"이미 노출이 잡히는 주제의 깊이"와 "필러당 코너스톤 1편"으로 돌린다.

### 라이브 사이트를 심사자 눈으로 본 결과 (오늘 curl로 확인)

1. **"Last reviewed October 11, 2026"이 71편 전부의 첫 줄**이다. 그 문장이 홈 카드 스니펫,
   `og:description`, 검색 스니펫의 첫 단어가 된다. 심사자에게 "같은 날 일괄 편집한 사이트"로 읽힌다.
   삽입 위치는 `generator/blogger_publish.py`의 `reviewed_line`이 본문 맨 앞에 넣는 구조다.
2. **구조 획일**: 71편 모두 `## Sources`, 68편 `## FAQ`, 70편에 표. 도입 답변→단계→표→FAQ→출처의
   같은 골격. 글 하나하나는 좋아도 70편을 훑는 심사자에게는 템플릿 양산으로 보인다.
3. **이미지 148장 전부 플랫 SVG 일러스트**, 사진 0장. "직접 해 본" 흔적이 사이트 어디에도 없다.
4. **책임자 없음**: 바이라인 숨김, 저자 페이지 없음, About은 "AI assistance" 고지만 있고 사람 이름이
   없다. 심사 사유인 "가치"는 결국 "누가 책임지는가"를 포함한다.
5. **라벨 171개 중 148개가 2편 이하**에 쓰임(예: DIY fixes / DIY repair / DIY repairs, HVAC /
   HVAC maintenance가 따로). 라벨 위젯이 지저분하고 라벨 페이지가 얇은 페이지 수십 개를 만든다.
6. **허브 없음**: 필러별 "여기서 시작" 페이지가 없다. 홈은 최신순 카드 나열뿐이다.
7. 정적 4페이지(About/Contact/Privacy/Terms)·HTTPS·ads.txt·JSON-LD·내부 링크는 이미 정상.

## 2. 전략

### 원칙

- **폭 → 깊이.** 새 필러·새 소주제 추가 중단. 노출이 잡힌 3개 주제 주변과 필러당 코너스톤 1편에 집중.
- **자동화가 못 만드는 것을 사람이 넣는다.** 사진·실측·실제 경험은 오너만 줄 수 있고, 중단 기준도
  이걸 "실질 변화"로 못 박았다. 이 항목이 비면 제출하지 않는다.
- **티 제거는 코드 한 줄짜리부터.** 날짜 줄 위치, 라벨 통합, 골격 변주는 비용이 거의 없다.
- **제출은 달력이 아니라 게이트로.** 11-04는 하한선이지 목표일이 아니다.

## 4. 오너 결재·결정 필요 항목

1. **편집 책임자 표기**: 실명 / 이니셜+성 / 익명 유지 중 선택. 익명 유지면 B축을 포기하는 것이고
   그만큼 통과 확률을 깎는다는 점을 전제로 결정.
2. **사진 제공**: 아래 8편 중 가능한 글. 글당 사진 3~5장(폰 촬영, 보정 불필요)과 "해 보니 이랬다" 5줄.
   furnace filter basics / pipes freeze temperature / space heater 8 hours cost / thermostat settings by season /
   garbage disposal humming / leftover rice / clothes worn once / musty laundry.
   예상 소요: 2~3시간, 2주 안에.
3. **Phase 1 주제 9개 교체**와 `target_words` 필드 추가(설정 필드 1개) 승인.
4. **제출 시점은 게이트 충족 시 세션이 보고 → 오너가 누름.** 세션은 제출 버튼을 누르지 않는다.
